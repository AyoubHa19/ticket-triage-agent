A ticket agent that knows when to hand over

Three small projects on the hard parts of a production agent: when to escalate to a human, grounding answers in a knowledge base, and measuring and running the LLM layer reliably. Everything below runs in your browser, using the same code the 140 tests run.

Inbox agent

Write a ticket the way a tenant or owner would. The agent either replies automatically, grounded in the knowledge base, or hands the ticket to a person and says why. Safety, legal and prompt-injection checks run on the raw text, so the model can never talk the agent out of an escalation.

Knowledge search

The same question through three retrievers: BM25 (word matching), vector (character n-gram embeddings, so typos and compounds still match) and hybrid (both, merged by rank fusion). The agent tool also decides whether the best hit is good enough to answer from at all.

LLM router

Providers fail: rate limits, overloads, timeouts, bad keys. Choose how two simulated providers behave and watch the real router retry with backoff, fall back, and open a circuit breaker after repeated failures.

Settings for the demo: 3 attempts per provider, backoff from 300 ms with jitter, 1.5 s timeout, breaker opens after 2 exhausted requests and stays open for 10 s. Providers are simulated; the router is the real code.
